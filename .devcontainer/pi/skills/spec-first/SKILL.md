# Spec first

1. Read the project's AGENTS.md and existing docs/SPEC.md.
2. Ask at most five focused questions about outcomes, constraints, and acceptance criteria.
   Ask only what cannot be learned from the repository; wait for answers.
3. Propose the smallest useful scope and make exclusions explicit.
4. After agreement, create or update the relevant section of docs/SPEC.md.
   Include observable behavior, edge cases, and acceptance criteria.
5. Show the spec change and ask for review before planning implementation.

Do not write application code, install dependencies, or invent project requirements.
Keep the next action visible and avoid turning a small request into a large framework.
